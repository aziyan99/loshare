# Data Model: Fix Sender Duplicate Download Bug

## State & Transition Mechanics

We trace the state transitions of the transfer session in both client and server memory to ensure correct scoping.

### Client-Side State (in `src/public/app.js`)

- `incomingTransfersMeta`: A key-value map mapping `transferId` -> `{ fileName }` for incoming transfers.
  - *Receiver Role*: Populated when `file-request` SSE event is received. Deleted when the download completes (`status === 'completed'`) or fails (`status === 'failed'`).
  - *Sender Role*: Remains empty (no entry exists for the `transferId` generated by this client).
- `currentTransferId`: Stores the `transferId` of the active transfer session.
  - Set on sender when initiating the metadata request.
  - Set on receiver when receiving the `file-request` SSE event.
  - Cleared on both sides when transfer completes or fails.

### State Transition Table

| Trigger | Transfer Status | Sender Action | Receiver Action |
| --- | --- | --- | --- |
| **Request Initiated** | `pending` | Sets `currentTransferId`. Shows progress modal. | N/A |
| **Request Received** | `pending` | N/A | Receives SSE `file-request`. Sets `currentTransferId`. Populates `incomingTransfersMeta`. Shows prompt modal. |
| **Accept Clicked** | `transferring` | N/A | Dispatches `/api/transfer/respond`. Shows progress modal. |
| **Upload Started** | `transferring` | Receives SSE `transferring`. Calls `startBinaryUpload` to post stream. Updates progress bar. | Receives SSE `transferring`. Updates progress bar. |
| **Upload Completed** | `ready` | Receives SSE `ready`. **Keeps modal open showing 100% / Completed upload (no download triggered)**. | Receives SSE `ready`. **Verifies metadata exists, triggers fetch to `/api/transfer/download`**. Shows saving modal. |
| **Download Completed** | `completed` | Receives SSE `completed`. Hides progress modal, clears `currentTransferId`. | Receives SSE `completed`. Hides progress modal, clears `currentTransferId`, deletes `incomingTransfersMeta`. |
